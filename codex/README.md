# codex

Most of the Codex configuration is generated from the `claude/` sources in the [agent-governance](https://github.com/nullvoidundefined/agent-governance) monorepo by `translate/codex.mjs`, then copied into `~/.codex` by the repo root's `sync.sh`.

Do not edit `~/.codex` directly, and do not hand-edit a generated file here: change the `claude/` source, run `node translate/codex.mjs --write` from the repo root to regenerate, then `./sync.sh` to install. `node translate/codex.mjs --check` verifies the tree is already current without writing anything; it runs in CI (`.github/workflows/enforce.yml`) and at `git push` (`claude/hooks/pre-push.sample`), so a source edit that never got `--write`ed fails the push rather than shipping stale.

`.claude-port.json` (per-file content hashes) and `PORT-STATUS.md` (the hook-by-hook port table) are themselves generated on every `--write` and carry the current counts. A `GENERATED by translate/codex.mjs` header names the source file each generated file came from; do not edit below that line. A handful of files are hand-authored instead, listed in `translate/codex-port-map.json`'s `hand_authored` array: `hooks/codex-hook-adapter.sh`, this `README.md`, `.gitignore`, and the two semantic-render skills (`skills/session-start/SKILL.md`, `skills/session-handoff/SKILL.md`), which carry a `Hand-ported` header instead of a `GENERATED` one and are edited directly.

The `.gitignore` here is also hand-authored: it is the allowlist of which generated files are tracked, so adding a new agent or skill on the `claude/` side needs a matching allowlist line here before `git add` will pick up what the translator wrote.
