# Vue Frontend Conventions

Vue 3.5+ with the Composition API and `<script setup lang="ts">` only (no Options API, no plain `<script>`). Follows `CLAUDE-FRONTEND.md` for everything not covered here. Nothing in the React file applies. Run `vue-tsc --noEmit` alongside `tsc` in CI.

## Stack

- `@tanstack/vue-query` for all server state; no `fetch` in `onMounted` or a `watch`.
- Nuxt `useState` composables for app state that outlives a component. Pinia only when a project needs a real store (many interdependent actions, store plugins, or Vue without Nuxt); use setup stores and `storeToRefs` when reading several fields.
- `openapi-fetch` over types generated by `openapi-typescript` from the backend's committed OpenAPI document. No hand-written API types.
- Reka UI for dialogs, toasts, menus, popovers and tabs, styled through the `class` prop. The toast lives in one `components/ToastRegion/` driven by `useToast()`. Never `role="button"` on a non-interactive element.
- Styles in a sibling `.module.scss`; no `<style>` block and no Tailwind.

## Files

- `composables/` holds every `useX` function (never `hooks/`). `stores/` exists only if Pinia is adopted, one store per file. No `utils/`; pure functions go to `services/`.
- Components `PascalCase.vue`, multi-word (`ChatBox.vue`); folder repeats the name (`components/ChatBox/ChatBox.vue`, tag is `<ChatBox>`). Composables `useX.ts`; app-state composables wrap one `useState` key named for the noun (`useThemePreference.ts`, key `'theme-preference'`). Pinia stores `themeStore.ts` exporting `useThemeStore`. Tests `PascalCase.test.ts` beside the component.

## Component shape

```vue
<script setup lang="ts">
/** Chat input for one trip. */
import { computed, ref } from 'vue';
import { useMutation } from '@tanstack/vue-query';
import { sendMessage } from '@/api/sendMessage';
import styles from './ChatBox.module.scss';

defineOptions({ name: 'ChatBox' });

interface Props {
    tripId: string;
    isDisabled?: boolean;
}
interface Emits {
    (event: 'sent', messageId: string): void;
}
const { tripId, isDisabled = false } = defineProps<Props>();
const emit = defineEmits<Emits>();
</script>

<template>
    <form :class="styles.chatBox" data-test-id="chat-box" @submit.prevent="submitDraftMessage"></form>
</template>
```

- Block order: `<script setup>` then `<template>`. Put a `/** what and why */` header as the first line inside `<script setup>`, not an HTML comment.
- Type-only `defineProps<Props>()` with defaults in the destructure (no `withDefaults`); `defineEmits<Emits>()` in call-signature form. Order: `defineOptions`, `defineProps`, `defineEmits`, `defineSlots`.
- `ref` for primitives and reassigned values, `computed` for derived values, `reactive` only for a local object never reassigned or destructured.
- Import explicitly from `vue` and `#imports` even though Nuxt auto-imports. Group 1 is `vue`, `vue-router`, `#imports`, `#app`.
- Handlers are named functions in the script (verb plus noun); no multi-statement inline handlers.
- No inline styles, except a runtime CSS custom property (`:style="{ '--progress': ratio }"`).
- Every component and page root has a kebab-case `data-test-id`.
- `v-for` takes a stable `:key` from the data, never the index; never `v-if` with `v-for` on one element.
- `v-html` is banned unless the input passes a sanitizer in `services/`, named at the call site.
- Slots over render props; type slot props with `defineSlots`. `provide`/`inject` only with a typed `InjectionKey`.
- Template refs via `useTemplateRef('name')`; clear timers and `EventSource` handles in `onBeforeUnmount`. No Vuex, event bus or global mutable module state.

## Data

- Wrap every query in a composable (`useTripsQuery.ts`) that owns the query key and gets the API client in setup. Never build query keys inline. `QueryClient` config lives in `config/queryClient.ts`, installed by a Nuxt plugin. `onError` routes to the toast.
- Never copy query data into app state; the query cache is the only copy of server state. `useState` composables own one SSR-safe `useState('<key>', () => initial)` and export functions that change it.
- `api/apiClient.ts` builds the client in `createApiClient()` (`createClient<paths>()`); `useApiClient()` memoizes it per Nuxt app instance. Never a module-level singleton. Each `api/` module is one function per route taking the client as its first parameter (`fetchTrips(apiClient, query)`).
- Call `useApiClient()` only in setup, never inside an `api/` function or after an `await`.

## Lint and tests

- `eslint-plugin-vue` `recommended` with `vue-eslint-parser`; `vue/block-order` script then template; `vue/multi-word-component-names` on (pages, layouts, `error.vue` exempt); `vue/no-v-html` as error; `vuejs-accessibility` recommended.
- Prettier template attributes use double quotes; `vueIndentScriptAndStyle: false`.
- Vitest with `happy-dom`, `@vue/test-utils` and `@testing-library/vue`; `@nuxt/test-utils` with `mountSuspended` for components needing the Nuxt runtime. Query by role and accessible name. Test app-state composables through their exported functions against a fresh Nuxt app; use a real `createPinia()` for a store under test.
- Storybook (`@storybook/vue3-vite`) for shared `components/ui/*` with Playwright `visual-regression` snapshots.
