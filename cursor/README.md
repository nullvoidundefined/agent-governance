# cursor

Most of the Cursor configuration is generated from the `claude/` sources in the [agent-governance](https://github.com/nullvoidundefined/agent-governance) monorepo by `translate/cursor.mjs`, then copied into `~/.cursor` by the repo root's `sync.sh`.

Do not edit `~/.cursor` directly, and do not hand-edit a generated file here: change the `claude/` source, run `node translate/cursor.mjs --write` from the repo root to regenerate, then `./sync.sh` to install. `node translate/cursor.mjs --check` verifies the tree is already current without writing anything; it runs in CI (`.github/workflows/enforce.yml`), beside the equivalent `translate/codex.mjs --check` gate, so a source edit that never got `--write`ed fails CI rather than shipping stale.

`.claude-port.json` (per-file content hashes) and `PORT-STATUS.md` (the hook-by-hook port table) are themselves generated on every `--write` and carry the current counts. A `GENERATED by translate/cursor.mjs` header names the source file each generated file came from; do not edit below that line. A handful of files are hand-authored instead, listed in `translate/cursor-port-map.json`'s `hand_authored` object with each file's B-9 class: `hooks/claude-hook-adapter.sh` (hand-authored-mapped, since Cursor's hook event vocabulary has no mechanical mapping from Claude Code's), and this `README.md` (hand-authored-local). The `.gitignore` is generated too, derived from the planned tree the same way `codex/.gitignore` is, so a missing allowlist entry for a newly generated file is a stale-file failure `--check` catches rather than an untracked file nobody notices.
