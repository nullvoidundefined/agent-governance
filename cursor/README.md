# cursor

Most of the Cursor configuration is generated from the `claude/` sources in the [agent-governance](https://github.com/nullvoidundefined/agent-governance) monorepo by `translate/cursor.mjs`, then copied into `~/.cursor` by the repo root's `sync.sh`.

Do not edit `~/.cursor` directly, and do not hand-edit a generated file here: change the `claude/` source, run `node translate/cursor.mjs --write` from the repo root to regenerate, then `./sync.sh` to install. `node translate/cursor.mjs --check` verifies the tree is already current without writing anything; it runs in CI (`.github/workflows/enforce.yml`) and at `git push` (`claude/hooks/pre-push.sample`), beside the equivalent `translate/codex.mjs --check` gate, so a source edit that never got `--write`ed fails the push rather than shipping stale.

`.claude-port.json` (per-file content hashes) and `PORT-STATUS.md` (the hook-by-hook port table) are themselves generated on every `--write` and carry the current counts. A `GENERATED by translate/cursor.mjs` header names the source file each generated file came from; do not edit below that line. A handful of files are hand-authored instead, listed in `translate/cursor-port-map.json`'s `hand_authored` object with each file's B-9 class: `hooks/claude-hook-adapter.sh` (hand-authored-mapped, since Cursor's hook event vocabulary has no mechanical mapping from Claude Code's), this `README.md`, and `commands/session-start.md` plus `commands/session-handoff.md` (hand-authored-local: these two have no `claude/agents/` source to translate from, being hand-distilled from R-001 and R-601/R-602, and carry a `Hand-ported` header instead of a `GENERATED` one). The `.gitignore` is generated too, derived from the planned tree the same way `codex/.gitignore` is, so a missing allowlist entry for a newly generated file is a stale-file failure `--check` catches rather than an untracked file nobody notices.

## Fidelity over hand-tuning

The always-on rules (`rules/000-global-rules.mdc`, `rules/001-session-types.mdc`, `rules/002-global-memory-index.mdc`) used to carry hand-tuned Cursor phrasing in place of several `claude/` sentences: a reworded R-001 procedure, an R-106 and R-601 rewritten around `~/.claude` instead of the agent-governance repo, an R-502 clause naming "Cursor's task list", and a convention-files table describing Cursor rule-fetch semantics instead of plain file reads. As of the first real regeneration (2026-09-17) those sentences render byte-identical to their `claude/` source instead, the same fidelity-over-hand-tuning tradeoff `translate/codex.mjs` already made: a rule file that drifts from its source silently is worse than one that reads slightly generic. The Cursor-specific detail that hand-tuning used to carry is not lost, only moved: it lives in `translate/cursor-port-map.json`'s `cursor_preamble` (the sentence `renderGlobalRules` prepends ahead of the verbatim `CLAUDE.md` body, naming the `rulebook-reference-*` rule fan-out and the `~/.cursor/hooks.json` adapter path) and `index_trailing_paragraph` (the sentence `renderMemoryIndex` appends after the verbatim `INDEX.md` body, naming the `sessionStart` re-injection and that Claude Code's per-project auto memory does not load under Cursor). Both fields render alongside the source body rather than replacing any of it, so the file carries the full upstream text and the Cursor-only addendum together.

## Accepted fidelity loss

Beyond the preamble and trailing-paragraph templating, a small number of hand-tuned Cursor rewordings had no port-map field to move into and are simply gone: the R-001 line's old "under Cursor..." asides, the R-106 and R-601 `~/.claude`-specific phrasing, and the R-502 Cursor task-list clause. This is a deliberate loss, not an oversight (`.superpowers/sdd/2026-09-17-cursor-exporter/cursor-shapes-study.md` section 7 rules on it), because the alternative is a growing set of per-rule Cursor overrides that drift from `CLAUDE.md` every time the source rule's wording changes and nobody remembers to re-diverge the port.
