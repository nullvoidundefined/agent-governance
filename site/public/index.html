Governance for AI coding agents

Rules your coding agent can’t talk its way around.

The security promise

It restricts. It never grants.

Installing agent-governance does not give your agent, or this project, any new permission on your machine. Every hook can say no. None of them can say yes to something your tool would otherwise refuse.

Only takes permissions away

Hooks sit at the tool-call boundary and can only deny or ask. Your agent’s own permission prompts stay exactly as they were.

Writes to three folders

~/.claude, ~/.cursor, and ~/.codex. Nothing else on your system is touched.

Never deletes your files

Sync removes a file only if it installed it, no longer ships it, and you haven’t edited it since. Everything else is left alone.

Hooks never phone home

No telemetry and no network calls from any hook. Install fetches lockfile-pinned npm packages for the enforcement tools, and that is the only download.

How it works

Prose is a suggestion. A gate is a guarantee.

An agent told a rule follows it most of the time. The times it doesn’t are late in a long session, under pressure, on the change that touches production. So every rule that can be mechanical is.

  1. 01 · Rules

    One rulebook, three tools

    A single source of truth, synced into Claude Code, Cursor, and the Codex CLI.

  2. 02 · Hooks

    Gates at the tool call

    Secrets, destructive commands, production databases, protected paths: refused before they run.

  3. 03 · TDD lock

    Tests before code

    Production writes are denied until a failing test is on record. Then the tests are locked.

  4. 04 · Review gates

    Nothing merges unreviewed

    A fresh-context reviewer on every PR, plus a strongest-model security review on anything touching a control.

Honest accounting

We tell you which rules are still prose.

Of 132 registered rules, 94 are enforced by code, 9 by an LLM judge in CI, and 29 are advisory. The manifest names every one and its enforcer.
