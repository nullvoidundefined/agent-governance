# Hardening PR 4: tool-call audit log

Plan: hardening control 7 (audit log), approved by the owner 2026-10-04 with
tamper resistance chosen as "local guarded log" (off-box shipping is a
separate, unapproved follow-up). Sibling specs:
`docs/specs/2026-10-04-harness-hardening.md`,
`docs/specs/2026-10-05-credential-reads.md`.

## Goal

After an incident, the owner can answer "what did the agent actually run, and
what did the guards stop?" from a record the agent did not write by hand and
cannot edit through its tools. This is the evidence that a later "I verified
everything" claim can be checked against.

## Threat model

- **Attack to stop:** an agent's account of its own work diverges from what it
  ran, and no independent record exists; or an agent edits or deletes the
  record after the fact.
- **Ceiling:** the log is written as the same OS user. A program the agent
  writes and runs can still change it. True tamper resistance needs shipping
  lines off-box, out of scope.
- **Never a blocker:** logging failures never block or slow a tool call.

## Where and what

- Directory: `${AGENT_AUDIT_DIR:-$HOME/.local/state/agent-audit}`, one file
  per UTC day, `YYYY-MM-DD.jsonl`, mode 0600, directory 0700.
- One JSON object per line, keys in this order:
  `ts` (UTC ISO-8601), `session` (payload `session_id`, else `-`), `event`
  (`tool` or `decision`), `tool` (tool name), `repo` (basename of the git top
  level of `cwd`, else `-`), `cwd`, `input` (summary, below), and for
  `decision` lines `hook`, `rule`, `decision` (`deny` or `ask`).
- Input summary: Bash `command`, Read/Write/Edit/NotebookEdit `file_path`,
  Grep/Glob `pattern` and `path`, Agent/Task `description`, an MCP tool's
  argument keys (names only). Capped at 2000 characters with a `...` marker.
  Values matching `claude/hooks/secret-patterns.txt`, and the value part of
  `password=`, `token=`, `Authorization: Bearer`, URL userinfo, are replaced
  with `***` before writing.

## Acceptance criteria

- A-1: a PostToolUse hook `audit-log.sh`, registered with matcher `.*`, writes
  one `tool` line per completed tool call in the format above.
- A-2: the input summary is redacted and capped as above; a test with a
  run-time-built credential-shaped value checks the value never reaches the
  file.
- A-3: denials and asks are logged: `infra-mutation-guard.sh`,
  `destructive-db-guard.sh`, `secret-scan.sh`, `protected-path-guard.sh` and
  the destructive-ops guards append one `decision` line through a shared
  sourced helper (`audit-log-append.sh`) when they emit deny or ask. A test
  drives one deny through each and finds the line.
- A-4: the hook never blocks: an unwritable directory, a missing `jq`, or a
  malformed payload exits 0 with no output, and the tool call proceeds.
- A-5: the first write of a UTC day removes `*.jsonl` files in the directory
  older than 30 days, and nothing else.
- A-6: the audit directory is protected like the security-review ledger: a
  Write, Edit or NotebookEdit to a path inside it, and a Bash command that
  writes, moves, truncates or deletes a path inside it (redirect, `rm`, `mv`,
  `cp` onto, `sed -i`, `truncate`, `tee`), is denied by
  `protected-path-guard.sh`, from any working directory. Reading it is
  allowed.
- A-7: guard corpus rows cover A-6 for Bash and run through the Codex and
  Cursor adapters; the PostToolUse hook is ported where the target has the
  event and marked in the port maps otherwise.
- A-8: a line is one `write` of at most PIPE_BUF bytes after capping, so
  concurrent sessions never interleave a line.
- A-9: every row already in `fixtures/guard-corpus.txt` keeps its decision.

## Invariants

- The hook writes nothing outside the audit directory and prints nothing.
- No line holds a value matched by the redaction rules.

## Non-goals

- Off-box shipping, hash chaining, or signing (needs separate approval).
- Reading or summarizing the log (the owner reads it with `jq`).
