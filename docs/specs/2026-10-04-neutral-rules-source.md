# Neutral rules source

## Goal

Today `claude/` is the primary: the prose rules are edited there, and
`translate/codex.mjs` and `translate/cursor.mjs` project them into `codex/`
and `cursor/`. A rule changed in a Codex or Cursor session has no supported
path back. This change moves the prose rules into a tool-neutral `rules/`
tree that any LLM edits, generates all three trees from it, and regenerates
automatically when `rules/` changes, so no tool is primary.

## Inputs

- `rules/GLOBAL.md`: the global rules (today `claude/CLAUDE.md`).
- `rules/stacks/<STACK>.md`: the stack conventions (today
  `claude/CLAUDE-<STACK>.md`), plus `CLOUD-DEPLOYMENT.md` and `PROTOCOL.md`.
- `rules/agents/*.md`, `rules/skills/<name>/SKILL.md`, `rules/prompts/*.md`.
- Tool-specific text inside any of these, marked as a block:
  `<!-- only: claude -->` ... `<!-- /only -->` (also `codex`, `cursor`, or a
  comma list such as `only: codex,cursor`).
- Unchanged: `claude/hooks/`, `claude/enforce/` and `claude/settings.json`
  stay in `claude/` as shared, Claude-shaped code that every tool already runs
  (Codex and Cursor through their adapters). Any LLM edits them directly.

## Outputs

- `claude/CLAUDE.md`, `claude/CLAUDE-<STACK>.md`, `claude/CLOUD-DEPLOYMENT.md`,
  `claude/PROTOCOL.md`, `claude/agents/`, `claude/skills/`, `claude/prompts/`:
  generated by a new `translate/claude.mjs`.
- `codex/` and `cursor/`: generated as today, now from `rules/`.
- Every generated prose file begins with one line,
  `<!-- generated from rules/<path>; edit there -->`. A file whose format
  needs frontmatter on line 1 (an agent or skill) carries it as the first line
  after the frontmatter instead.
- `translate/all.mjs --write | --check`: runs the three generators. `--check`
  exits 0 when every tree matches `rules/`, 1 when any is stale, 2 on a source
  error, the same contract the existing translators use.

## Acceptance criteria

- B-1: `node translate/claude.mjs --write` on the migrated `rules/` produces
  `claude/` prose files byte-identical to the pre-migration files apart from
  the generated header line.
- B-2: `node translate/codex.mjs --write` and `cursor.mjs --write` reading
  `rules/` produce `codex/` and `cursor/` byte-identical to their
  pre-migration output.
- B-3: an `only: codex` block appears in the Codex output and in neither
  other output; a block with no `only:` tag appears in all three.
- B-4: an unclosed or nested `only:` block makes every generator exit 2,
  naming the file and line.
- B-5: `node translate/all.mjs --check` exits 1 after a `rules/` edit that was
  not regenerated, and names each stale output file.
- B-6: `./sync.sh` runs `translate/all.mjs --write` before installing, and
  prints the count of files it regenerated when that count is nonzero.
- B-7: `protected-path-guard.sh` denies a Write or Edit to a file whose
  generated header names a `rules/` source, and its message names that source.
- B-8: the guard allows Write and Edit to files without the header, including
  `claude/hooks/*.sh` and `claude/enforce/**`.
- B-9: CI (`.github/workflows/enforce.yml`) runs `node translate/all.mjs
  --check` on ubuntu and macOS.

## Invariants

- One source per rule: no prose rule exists in two edited places.
- Regeneration is deterministic: two `--write` runs on the same `rules/`
  produce identical bytes.
- The migration changes no rule's text in any tool's output (B-1, B-2).

## Failure modes

- A generator fails on a malformed `rules/` file: exit 2 with the file and
  line; `sync.sh` then stops before installing, so a broken source never
  reaches `~/.claude`, `~/.codex` or `~/.cursor`.
- Someone hand-edits a generated file outside an agent (an editor, `sed`):
  the guard does not see it; the next `--write` overwrites it, and CI
  `--check` fails if the hand edit was committed. Accepted.
- A session in a tool that has not run `sync.sh` reads stale rules. Same
  failure that exists today; unchanged.

## Non-goals

- Reverse translation from a generated file back to `rules/`.
- Merging concurrent edits across trees (one source makes it unnecessary).
- Moving hooks or `enforce/` out of `claude/` (owner decision 2026-10-04:
  they stay, as Claude-shaped shared code).
- A separate change log or ledger: the git log of `rules/` is the log.

## Dependencies

Node 22 (already required by the translators). No new packages.

## Security

`protected-path-guard.sh` gains a read of the first lines of the target file.
It reads only files the agent is already writing; no new input source.

## Delivery

Three PRs, each standard risk:

1. Create `rules/` by moving the prose sources, add `translate/claude.mjs` and
   `translate/all.mjs`, and the `only:` block parser (B-1, B-3, B-4).
2. Point `codex.mjs` and `cursor.mjs` at `rules/` (B-2, B-5, B-9).
3. `sync.sh` regeneration and the generated-file guard (B-6, B-7, B-8).
