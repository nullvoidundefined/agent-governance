# Neutral Rules Source Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the prose rules into a tool-neutral `rules/` tree that any LLM edits, generate `claude/`, `codex/` and `cursor/` from it, and regenerate automatically, so no tool is primary.

**Architecture:** One shared loader (`translate/rule-sources.mjs`) reads `rules/` and filters `only:` blocks per target. A new `translate/claude.mjs` writes the Claude prose files; `codex.mjs` and `cursor.mjs` switch their inputs to the same loader. `translate/all.mjs` runs all three. `sync.sh` regenerates before installing, and `protected-path-guard.sh` refuses agent edits to any file carrying a `GENERATED` header.

**Tech Stack:** Node 22 ES modules, `node:test`, bash 3.2 (hooks, `sync.sh`).

**Spec:** `docs/specs/2026-10-04-neutral-rules-source.md` (approved by the owner 2026-10-05).

## Global Constraints

- Node 22; no new npm packages.
- Generated prose files carry the existing header format: `<!-- GENERATED by translate/<builder>.mjs from <source>. Do not edit; change the source and run: node translate/<builder>.mjs --write -->` (`renderGeneratedHeaderFor` in `translate/exporter-core.mjs`). This replaces the spec's illustrative `generated from rules/X; edit there` wording so every tree uses one header and one guard pattern.
- `--check` exit codes: 0 current, 1 stale, 2 source error (existing contract).
- `claude/hooks/`, `claude/enforce/`, `claude/settings.json`, `claude/global-memory/`, `claude/rules/` (symlinks), `claude/README.md`, `claude/SETUP.md`, `claude/ISSUES.md`, `claude/KNOWN-ISSUES.template.md` stay hand-authored in `claude/` (owner decision 2026-10-04).
- Bash code is bash 3.2 compatible.
- Writing style: no em dashes (the `no-em-dash` hook enforces it).
- Standard risk. Test-first per `tdd-gated-dispatch` (cross-model test author, RED commit before implementation, one review).

## Spec clarifications made by this plan

- **B-2 byte-identity:** after the switch, `codex/` and `cursor/` output is byte-identical except the `from <source>` part of each GENERATED header, which now names the `rules/` path. Everything below the header must match.
- **Skill support files** (`rules/skills/*/scripts/*`) are copied verbatim with their mode and carry no header, so the generated-file guard does not cover them. Their staleness is still caught by `--check`.

## Review Focus

1. **Frontmatter files:** an agent or skill whose header line lands before `---` breaks Claude Code's frontmatter parse. Expected: the header goes on the first line after the closing `---`. Test in Task 2.
2. **Orphans inside `claude/`:** the Claude generator must never delete a hand-authored file (hooks, enforce, settings). Expected: orphan sweeping is limited to `claude/agents/`, `claude/skills/`, `claude/prompts/`, plus root-level `claude/*.md` files that carry a GENERATED header. Test in Task 2.
3. **`only:` blocks inside fenced code:** an `<!-- only: x -->` inside a code fence in a rules doc is still a directive (no fence awareness). Expected: documented, and the parser reports the line of any unbalanced tag. Test in Task 1.
4. **CRLF sources:** a rules file saved with CRLF line endings. Expected: the output keeps the source's bytes apart from the header; the `only:` tag regex accepts a trailing `\r`. Test in Task 1.
5. **`sync.sh` without node:** a machine where node is missing. Expected: `sync.sh` prints one warning and installs the committed trees (CI keeps them current), and does not abort. Test in Task 6.

```js
// only-blocks.mjs: keeps the parts of a rules/ document meant for one target.
// A block opens with `<!-- only: a,b -->` on its own line and closes with
// `<!-- /only -->`; both tag lines are dropped. Untagged text is kept for
// every target. Tags are matched on whole lines only (no code-fence
// awareness: a tag inside a fence is still a tag).
import { SourceError } from "./exporter-core.mjs";

const TARGETS = new Set(["claude", "codex", "cursor"]);
const OPEN = /^<!-- only: ([a-z, ]+) -->\r?$/;
const CLOSE = /^<!-- \/only -->\r?$/;

export function selectForTarget(text, target, file) {
  if (!text.includes("<!-- only:") && !text.includes("<!-- /only")) return text;
  const lines = text.split(/(?<=\n)/);
  let out = "";
  let open = null;
  lines.forEach((line, i) => {
    const bare = line.replace(/\n$/, "");
    const opened = OPEN.exec(bare);
    if (opened) {
      if (open) throw new SourceError(file, `line ${i + 1}: nested only: block (outer opened on line ${open.line})`);
      const names = opened[1].split(",").map((s) => s.trim()).filter(Boolean);
      for (const n of names) if (!TARGETS.has(n)) throw new SourceError(file, `line ${i + 1}: unknown target ${n}`);
      open = { line: i + 1, keep: names.includes(target) };
      return;
    }
    if (CLOSE.test(bare)) {
      if (!open) throw new SourceError(file, `line ${i + 1}: /only with no open block`);
      open = null;
      return;
    }
    if (!open || open.keep) out += line;
  });
  if (open) throw new SourceError(file, `line ${open.line}: only: block is never closed`);
  return out;
}
```
