1. LOWs are waived under the standing waiver. Record them in one follow-up
   ticket per PR; never fix them in the PR.
2. One general round and one security round. A second round only for a
   HIGH, or a MEDIUM fixed in code.
3. No scope added mid-PR. New ideas go in a follow-up PR.
4. About 90 minutes per high-risk task. Past that, stop and report to the
   owner with a recommendation.
5. Guard bypass severity: HIGH only when a non-adversarial agent would
   plausibly type it in normal work. Obfuscation-only bypasses are at most
   LOW (#214).

The owner pre-approved merging each of these PRs when green.

Working practices that avoid the hangs seen today:
- Never put a probe command (cloud, SQL, credential read) on a background
  agent's own Bash line: the live guards answer "ask" and the agent hangs.
  Write probes to a file and run them through a runner script.
- Use unique scratchpad log names per agent.
- Run the corpus with `GUARD_CORPUS_JOBS=4`.
