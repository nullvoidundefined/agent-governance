# Record the session start timestamp at SessionStart (R-503)

## Summary

R-503 asks every multi-task session to capture a start timestamp, and the ticket-lifecycle skill's `open` operation writes that timestamp as the ticket's `started_at`. Both depended on the model remembering when the session began. On 2026-09-18 a session opened a ticket with a recalled `started_at` of 08:30Z when the session had actually started at 08:51:37Z. The 21-minute error overstated `actual_minutes` (53 against a true 31) and inverted the R-906 recalibration, since the `estimate_ratio` came out at 1.18 instead of 0.69, which told the next estimate to grow when it should have shrunk.

The session transcript already carries the true start as its first `timestamp` field. This PR makes `hooks/session-start.sh` read that value at every session start, record it once per session, and inject it into the model's context, so the skill reads `started_at` instead of recalling it.

## What changed

- `claude/hooks/session-start.sh` gains `record_session_start`. It derives the project key and session ID from `transcript_path` exactly as `task-state-tracker.sh` does, and writes one UTC ISO-8601 line to `session-start.<session-id>` in the session's project directory under the Claude home. The value is the first `timestamp` in the first 50 transcript lines; when no transcript is on disk yet, which is the normal case on a fresh startup, the hook's own clock is used, because the hook runs at the session start by definition. The record is write-once, so compaction and resume re-inject the original value; a record that does not parse as ISO-8601 is rederived. Records from other sessions older than 14 days are pruned, the same retention clock `check_interrupted_tasks` uses. The value is injected as a `## Session start (R-503)` context block, with the record path rendered under `~`.
- `claude/hooks/tests/session-start-timestamp.test.sh` is the new fixture, declaring `# Covers: hook:session-start` for the R-516 closure check. It has 17 cases covering the transcript source, write-once behaviour across compact and resume, replacement of a corrupt record, the clock fallback, the no-`transcript_path` case, pruning, and the absence of the real home path in the context.
- `claude/skills/ticket-lifecycle/SKILL.md` `open` step 4 now reads `started_at` from the context block, falls back to the record file, and otherwise leaves the field empty and says so. It never estimates the value or substitutes the current time. `claude/skills/task-start/SKILL.md` step 4 points at the same block.
- `claude/CLAUDE.md` tags R-503 `[hook:session-start, manual]`; `claude/rulebook/reference.md` adds the session-start bullet to the Spec and rewrites the Enforcement line to split the mechanized half from the manual half; `claude/enforce/manifest.json` registers `R-503 -> hook:session-start` at the advisory tier.
- `claude/enforce/hook-hashes.txt` is regenerated for the changed hook, the new fixture, and the manifest. `codex/` and `cursor/` are regenerated by their translators.

## Architectural decisions

- **Extend `session-start.sh` rather than add a new hook.** A separate hook would have to be registered in `settings.json`, classified in both port maps, and added to the SessionStart latency budget, and it would duplicate the payload parsing `session-start.sh` already does. Extending the existing hook runs it under Codex and Cursor through their existing adapter lines with no port-map change, although under Cursor it records nothing yet, because that adapter does not pass `transcript_path` (see the review round below). The cost is a longer file, which already carries three other responsibilities.
- **The transcript's first timestamp over the hook's clock.** The user named the transcript as the authoritative source, and it is also the value anyone auditing the session later would read. The clock is the fallback only because a fresh session's transcript is often not yet written when SessionStart fires.
- **Inject into context as well as writing a file.** A file alone would require the model to know its own session ID to find it. The injected block is re-emitted on every source, compaction included, so the value survives summarization; the file is what keeps that re-emitted value stable.
- **Keyed by `transcript_path`, not by repo.** The existing `claude-session-start-sha-<repo>` stamp is keyed by repository, which is correct for commit counts but wrong here, because two parallel sessions in one repository start at different times.

## Testing

- `claude/hooks/tests/run-tests.sh`: all hook fixtures pass, including the existing `session-start.test.sh`.

The first run caught `skills-lint.test.sh` rejecting a `~/.claude/projects/` path cited in the skill, since that path is runtime state rather than a file in the claude tree; the skill now describes the location instead of citing it.

## Reflection

- R-503 has four clauses and only one of them, capturing the timestamp, is mechanized here. The percentage announcements and the elapsed-time report remain manual, and the tag says so explicitly with `[hook:session-start, manual]`, rather than implying the whole rule is now enforced.
- The first draft of the skill text cited the record's runtime path. `skills-lint` rejects any `~/.claude/...` citation that does not exist in the repo's claude tree, which is the right behaviour, since a reader following that citation from the repo would find nothing.
- The Linear tracker server connected only partway through the session, so the ticket (IAN-91) was opened after the implementation rather than at classification. Its `started_at` was taken from this session's first transcript timestamp by hand, which is the lookup the new hook now does automatically.
- The full suite failed `hook-latency.test.sh` on the SessionStart:resume chain (1573ms against a 400ms budget), and I first attributed it to machine load, which was wrong. The failure reproduced only when `CLAUDE_PROJECT_DIR` was set, as it is inside the R-509 Stop gate: the fixture runs the chain against a sandboxed HOME, `harness-sync.sh` then resolved this repo through that variable, saw the empty sandbox as drift, and ran a full sync on every timed round. It fails identically on `main` (1369ms), so it predates this PR, but it blocked this PR's gate, so a separate `fix(enforce)` commit here makes the fixture unset the variable before measuring. The budget is unchanged, and the chain measures 215 to 222ms with the variable set.

## Review round 1 (Copilot)

- **Shape-only validation.** The first version accepted any string of the right shape, so `2026-99-99T99:99:99Z` would have been recorded and injected. `is_utc_instant` now also parses the whole-second part with jq and requires the round trip to reproduce it, which rejects impossible months, days, and hours, both in an existing record and in a transcript value.
- **Clock persisted at the wrong time.** The first version fell back to the hook's clock whenever the transcript offered no timestamp, and then kept that value forever. On a `resume` or `compact` start the clock is later than the real start, so it could have recreated the exact error this PR exists to prevent. The clock is now used only on a `startup` or `clear` start; any other start with no record and no transcript timestamp writes nothing and injects nothing, and the skill then leaves `started_at` empty.
- **Retention rounding.** `find -mtime +14` rounds to whole days and kept records for almost 15 days. The prune now uses `-mmin +20160`, the exact 14 days that `check_interrupted_tasks` enforces.
- **Cursor coverage.** The Cursor adapter rebuilds the SessionStart payload without `transcript_path`, so no record is written under Cursor. The skill, the rulebook Spec, and the manifest note now say so, and the skill's existing "neither present: leave it empty" branch is the Cursor behaviour. Passing a session identity through the Cursor adapter is a separate change to a hand-authored adapter and its contract tests, filed as a follow-up rather than folded into this PR.
- Seven new fixture cases covered these four points; all seven failed before the fix and pass after it.
