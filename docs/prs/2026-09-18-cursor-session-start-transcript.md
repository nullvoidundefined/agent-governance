# Record the R-503 session start under Cursor

## Summary

PR #36 made `hooks/session-start.sh` record each session's start timestamp and inject it as a `## Session start (R-503)` block, which ticket-lifecycle's `open` reads as `started_at`. The hook keys that record on the SessionStart payload's `transcript_path`: the parent directory name is the project key and the file basename without `.jsonl` is the session ID. The Cursor adapter rebuilt the payload with no `transcript_path`, so every doc that described the feature carried a caveat saying that Cursor gets no block.

That caveat was also wrong about what Cursor actually got. `session-start.sh` read its three payload fields as one tab-separated line, and because tab is an IFS whitespace character, `read` folds consecutive tabs together. With `transcript_path` empty, the line `startup<TAB><TAB>/path/to/workspace` split into two fields, and the workspace path landed in `TRANSCRIPT_PATH`. Under Cursor the hook therefore wrote a record keyed on the workspace's parent directory name, with the workspace's own folder name as the session ID. Because the record is write-once, every later Cursor conversation in that workspace re-read the first conversation's start, so `started_at` was stale for every conversation after the first until the 14-day prune removed it.

This PR fixes both problems. The adapter now passes a synthetic, stable `transcript_path` for each Cursor conversation, and `session-start.sh` parses its payload on a separator that preserves empty fields.

## What changed

- `cursor/hooks/claude-hook-adapter.sh` gains `synthetic_transcript_path`, which returns `$HOME/.claude/projects/cursor-<first 16 hex of sha256(ROOT)>/<conversation_id>.jsonl`, with the conversation ID sanitized the same way the adapter already sanitizes it for its findings file. The path names a file that is never created. `handle_session_start` adds it to the SessionStart payload only when Cursor sent a real `conversation_id`. When the ID is absent or is the adapter's `"default"` fallback, the field is left out, because a shared `default` session ID would give every conversation one write-once start. The hash uses `shasum -a 256`, falls back to `sha256sum`, and falls back again to `cksum`, so the key is stable on macOS, on Linux, and on a minimal container.
- `claude/hooks/session-start.sh` joins the `source`, `transcript_path`, and `cwd` fields with U+001F (the ASCII unit separator) and reads them with `IFS=$'\x1f'`. A non-whitespace IFS character keeps empty fields, so an empty `transcript_path` stays empty. The `record_session_start` comment now describes the Cursor path instead of saying Cursor gets no record.
- `claude/hooks/tests/session-start-timestamp.test.sh` adds a case with the exact payload shape the adapter sent before this PR (`source` and `cwd`, no `transcript_path`) and asserts that the hook injects no start block and writes no projects tree. The existing no-`transcript_path` case sent `{}` with no `cwd`, so it could not reach the field collapse.
- `claude/enforce/tests/cursor-adapter-contract.test.sh` adds a fourth section that runs the real adapter over the real `session-start.sh` inside the fixture's sandbox. It asserts that a conversation gets the block and a record under a `cursor-<hash>` key, that the synthetic transcript never appears on disk, that a second start of the same conversation re-reads a planted record instead of the clock, that a second conversation in the same workspace gets its own record, and that a payload with no `conversation_id` or with `"default"` gets no block and no record.
- The Cursor caveats are replaced with the new behaviour in `claude/skills/ticket-lifecycle/SKILL.md` step 4, the R-503 Spec in `claude/rulebook/reference.md`, and the R-503 note in `claude/enforce/manifest.json`. `cursor/` and `codex/` are regenerated by their translators, and `claude/enforce/hook-hashes.txt` is regenerated.

## Other SessionStart hooks given a transcript that does not exist

The Cursor `sessionStart` line runs seven hooks. Each was checked for how it treats a `transcript_path` naming a missing file:

- `session-start.sh` `record_session_start` reads the transcript with `head -50 ... 2>/dev/null`, gets nothing, and takes the clock branch, which is allowed because the adapter always sends `source: "startup"`.
- `session-start.sh` `check_resume_drift` returns immediately on any source other than `resume`, and the adapter never sends `resume`.
- `session-start.sh` `check_interrupted_tasks` scans `task-state.*.jsonl` in the `cursor-<hash>` directory. Nothing writes task-state files there, because `task-state-tracker.sh` also keys on `transcript_path` and the adapter's PostToolUse payloads carry none, so the loop finds no files and emits nothing. If a file did appear, the liveness check looks for `<sid>.jsonl`, finds it missing, and falls through to the normal 14-day TTL, which is the same path an ended Claude Code session takes.
- `parallel-session-check.sh` reads only `cwd` from its payload.
- `harness-sync.sh`, `hookspath-drift-check.sh`, `enforcement-guard-check.sh`, and `hook-integrity-check.sh` never read `transcript_path`, and `redaction-guard-check.sh` mentions the word only in prose.

## Architectural decisions

- **A synthetic path in the adapter rather than a Cursor branch in `session-start.sh`.** The alternative was to teach `session-start.sh` a second keying scheme, for example a `session_id` field. That would put Cursor knowledge into a hook that is otherwise tool-neutral, and `check_interrupted_tasks` and the task-state tracker would need the same second scheme. Translating Cursor's identity into the shape Claude Code already sends keeps every hook unchanged, which is the adapter's stated job.
- **A hashed workspace key rather than Claude Code's slash-to-dash key.** Using Claude Code's own directory name for the workspace would place Cursor records beside Claude Code's records for the same repository, and a Cursor conversation ID could then be mistaken for a Claude Code session by anything that scans that directory. The `cursor-` prefix keeps the two apart, and the hash keeps the key short and free of path characters.
- **Fix the field collapse in this PR rather than in a follow-up.** Without the parser fix, a Cursor payload with no `conversation_id` would still record against the workspace path, so the "skip when absent" requirement could not be met. The two changes are one behaviour.

## Testing

- The new `session-start-timestamp.test.sh` case failed on both of its assertions before the parser change and passed after it.
- The new contract section failed on 6 of its 10 cases before the adapter change. Four cases passed before any change, and the parser bug is the reason: with the fields collapsed, the old adapter already produced a block and a record, keyed on the workspace path. After both changes all 10 pass.
- `claude/hooks/tests/run-tests.sh`: ALL HOOK TESTS PASS.
- `claude/enforce/tests/run-tests.sh`: ALL ENFORCEMENT TESTS PASS, including `translate-cursor.test.sh` and `translate-codex.test.sh`.

## Reflection

The first contract run surprised me: cases that should have failed before the adapter change passed. I had assumed that a missing `transcript_path` meant an empty one, and that is how the PR #36 comment described Cursor. Running the adapter by hand showed a record keyed on the sandbox's parent directory, which led to the tab-folding behaviour of `read`. The existing fixture could not see it because its no-`transcript_path` case had no `cwd` either. What I understand now is that a hook fed by an adapter needs its fixtures to use the adapter's real payload shape, not the smallest payload that omits the field under test.

## Why this is a separate PR

- This work was merged into the `feat/session-start-timestamp` branch after #36 had already been squash-merged from an earlier head, so it never reached `main`. It is re-landed here as the two original commits cherry-picked onto `main`.
- #36 also merged before the R-503 Spec line and the manifest note were updated for the narrowed clock fallback in `17652f1` (the clock is used only on a `startup` or `clear` start whose transcript file does not exist yet). This PR carries that wording fix, which also describes the Cursor path correctly: the synthetic transcript never exists on disk, so a Cursor conversation records the clock once and re-reads that record afterwards.

## Review round 1 (Copilot)

- **Lossy session id.** The synthetic path reused `SAFE_ID`, the findings-file name component, which maps every unsafe character to `_`, so `conv/a` and `conv_a` named one write-once record and the second conversation would have inherited the first one's start. An id that sanitizing leaves unchanged is still used as it is, so the context block stays readable; an id that sanitizing changed gets a digest of the raw id appended. The digest helper is shared with the workspace hash.
- **Workspace isolation untested.** The contract exercised one workspace only. It now starts the same conversation id under a second root and asserts a second `cursor-<hash>` directory and a separate record. That case passed before the fix, since the workspace hash was already correct; it is there so a constant hash cannot slip in later. The collision case failed before the fix and passes after it.
