# PR: R-605 ticket-reference gate on `gh pr create`

Ticket: IAN-119. Branch: `feat/r605-ticket-ref-gate`.

## Summary

R-605 asks for a tracker ticket on every task above the trivial tier and for its key on every commit's `Refs:` trailer, but until this PR it was tagged `[manual]` and had no entry in `claude/enforce/manifest.json`. The 2026-09-19 ticket audit found about 14 non-trivial pull requests that shipped with no ticket. Every one of them traced to a session that never ran `task-start` (where the ticket is opened), to a spawned-task prompt that described the fix without mentioning a ticket, or to a web session where `~/.claude/TICKET-TRACKER.json` does not exist. This PR adds a PreToolUse gate that refuses `gh pr create` when neither the pull request's commits nor its body carry a `Refs: <KEY>` line, registers it as R-605's enforcer, and adds the ticket step to the guidance for writing handoff prompts, so that the most common way of losing the ticket is caught at the last point where fixing it is cheap.

## What changed

- `claude/hooks/pr-ticket-ref-gate.sh` (new) fires on `gh pr create` (and its alias `gh pr new`). It allows silently when a line of the form `Refs: <KEY>`, with KEY matching `[A-Z][A-Z0-9]+-[0-9]+`, appears in any commit message in the pull request's range or in the text passed with `--body`/`-b` or `--body-file`/`-F`. It also allows silently when every changed path in the range is a Markdown file or sits under `docs/`, and when `.claude/task-tier.json` records the trivial tier for the branch that is checked out. When none of those hold and `~/.claude/TICKET-TRACKER.json` is absent, it allows but adds context naming R-605's degraded path and the handoff fields to record. Otherwise it denies with a reason that names R-605, `/ticket-lifecycle`, and the `Refs: <KEY>` fix. Fires are logged through `log-rule-fire.sh` as `deny` or `warn`.
- `claude/enforce/tests/pr-ticket-ref-gate.test.sh` (new) covers the deny, both commit and body references (inline, heredoc, `--body=`, `-b`, `--body-file`, `-F`), the docs-only and trivial-tier exemptions and their near misses, the warn-and-allow path under a sandboxed HOME, look-alike strings (`R-605`, `SHA-256`, a bare `IAN-119`, `Refs: R-605`), a `Refs:` line in the title only, a `-b` belonging to an earlier command in the chain, a `cd <repo> &&` prefix and a chain of `cd`s, a directory outside any repository, text from a later command in the chain (a heredoc, a `-F`, a quoted `Refs:` line), a heredoc body holding quotes and separators, the registration carrying no `if` filter, commands that are not `gh pr create`, and a branch that was already pushed with no base override.
- `claude/settings.json` registers the hook in the PreToolUse Bash chain after the push gates, with no `if` filter, so compound commands reach it. `claude/enforce/manifest.json` gains an R-605 entry (tier `regex`, enforcer `hook:pr-ticket-ref-gate`, severity `error`) naming the fixture.
- `claude/CLAUDE.md` changes R-605's tag from `[manual]` to `[hook:pr-ticket-ref-gate]` and adds the handoff-prompt clause to its norm line. `claude/rulebook/reference.md` adds a "Handoff prompts" bullet to R-605's Spec and rewrites its Enforcement paragraph. `claude/rulebook/agents.md` adds the same requirement to R-701's Spec, which is where dispatch-prompt content is specified and which `spec-grounding` and `tdd-gated-dispatch` already cite. The ticket-lifecycle design's Non-goal that ruled out a hook is marked superseded, with its original reasoning kept.
- `claude/README.md` describes the new gate beside the push gates. The Codex and Cursor ports (`codex/`, `cursor/`) and `claude/enforce/hook-hashes.txt` are regenerated.

## Architectural decisions

- **The PR base, not `resolve-outgoing-base.sh`.** The brief suggested reusing the push gates' base resolver. Its first choice is the branch's own `@{push}` tracking ref, and a branch is normally pushed before its pull request is opened, so that range would be empty and every PR would look as if it carried no commits. The gate instead resolves the pull request's base: `--base`/`-B` if given, then origin's default branch, then `origin/main`, `main`, `origin/master`, `master`, merged with HEAD. `CLAUDE_ENFORCE_BASE` still overrides, as it does for the push gates. A fixture pushes the branch first to prove the difference.
- **A `Refs:` line, not a bare key.** A bare key match would accept `R-605` or `SHA-256` anywhere in a message. The gate requires `Refs:` at the start of a line, with only whitespace or an opening quote before it, and a key with at least two characters before the hyphen, so `Refs: R-605` does not count either. The alternative, parsing trailers with `git interpret-trailers`, was rejected because the body side has no such parser and one rule for both sides is easier to reason about.
- **Body parsing is bounded to the `gh` invocation, not tokenized.** `git-invocation.sh`'s tokenizer splits on quotes, and a heredoc body that contains a double quote would split mid-body and lose its line structure. The gate instead cuts the command at the `gh pr create` word, then scans forward to the first unquoted `;`, `&`, `|`, or newline, tracking quotes and skipping a heredoc whole, so a later command's heredoc or `-F` cannot supply the body (a Copilot finding on the first version, which read everything after `--body`). Inside that invocation it takes the text after the first `--body`/`-b` and looks for a line that begins with `Refs:`, so a `--title 'Refs: X-1'` after the body does not count, and an earlier `git checkout -b` in the chain is not taken for the body.
- **The `cd` chain is replayed, and no repository is not an exit.** The first version honored only the first `cd` and exited silently when the directory was not a repository, so `cd /tmp && cd <repo> && gh pr create` bypassed the gate (another Copilot finding). The gate now replays every `cd` before the invocation, each relative to the one before, and outside a repository it still checks the body and then warns or denies.
- **A trivial ledger counts only for the current branch.** `.claude/task-tier.json` is session state and can survive from an earlier task. The gate honors a trivial tier only when the ledger's `branch` matches the checked-out branch (or records none).
- **An empty range is not docs-only.** An empty diff would pass "every changed path is docs" vacuously; the gate treats it as not exempt so a wrongly resolved base cannot turn into an allow.
- **No `if` filter on the registration.** The first version registered the hook with no `if` filter, so compound commands reach it. Copilot's review pointed out that the filter is a prefix match, so `cd <repo> && gh pr create` would never reach the hook. The registration now has no `if`, and the hook's own regex does the match; a non-matching command costs one `jq` call and one `grep` before the hook exits (about 10 ms). A fixture asserts the registration carries no filter.
- **No `exempt-repos.txt` check.** The push gates honor that allowlist because it exists to switch off lint conventions for foreign repositories. R-605 is about the operator's own tracking, so the gate does not consult it.

## Testing

The fixture was written first and run before the hook existed: it exited 1 with 17 failing assertions (the passing ones were the silent-allow cases, which a missing hook satisfies vacuously). After the hook was added it passes every assertion. `bash claude/enforce/tests/run-tests.sh` and `bash claude/hooks/tests/run-tests.sh` both pass in full, including `manifest.test.sh`, `manifest-fixture-closure.test.sh`, `enforcement-guard-check.test.sh`, `deny-tier-set-convention.test.sh`, and `guard-fail-closed.test.sh`, which probes the new hook with empty, malformed, and non-string input. `shellcheck --severity=error` is clean over `claude/hooks/*.sh claude/enforce/*.sh sync.sh`, and `node translate/codex.mjs --check` and `node translate/cursor.mjs --check` both exit 0 after `--write`.

## Reflection

The part that needed the most thought was the base. Reusing the push gates' resolver looked like the obvious, consistent choice, and it would have passed every fixture that pinned `CLAUDE_ENFORCE_BASE`, while in real use it would have compared a pushed branch against itself. Only the fixture that pushes the branch first, with no override, shows that difference, and it is the case that matters. The first draft also matched `-b` anywhere in the command, which a chained `git checkout -b` would have tripped; scoping the flag search to the `gh` invocation fixed that. Copilot's first review then found three bypasses in how the command was read (the first `cd` only, an unbounded body tail, and a prefix `if` filter), which share one cause: I treated the command string as if it held a single invocation, when a real Bash tool call is usually a chain.
