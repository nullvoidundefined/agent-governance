# Deny the common ways the agent can skip git hooks

Refs: IAN-141

## Summary

Before this change, the harness only asked for confirmation when the agent typed `git commit --no-verify` or `git commit -n`, through two literal-prefix rules in `claude/settings.json`. A prefix rule cannot see an abbreviated flag (`--no-veri`), a flag behind a global option (`git -c x=y commit -n`), a different subcommand (`git push --no-verify`), a quoted or escaped flag, a wrapper (`sudo`, `bash -c`, `eval`), or any of the ways to skip hooks that are not a flag at all. The 2026-09-19 ECC audit ranked this as port item 2. This change makes `destructive-command-guard.sh` deny those forms on every attempt, on a parse of the command that follows bash's own quoting rules, and keeps ordinary developer commands that look similar working. It is a guard against habit and accident, not a sandbox; IAN-155 tracks a spelling-independent backstop.

## What changed

- **Parsing (B-5, B-6).** The new companion `claude/hooks/shell-command-segments.py` splits a command into simple commands the way bash does. It resolves quotes, backslash escapes, `$'...'` strings, line continuations, and comments. It skips heredoc bodies unless they feed a shell, and parses command substitutions and the command strings given to `sh -c` or `eval` as further commands. It drops wrappers (`env`, `sudo`, `command`, `exec`, `nohup`, `time`, `nice`, `timeout`, `xargs`) with their own options, and drops compound-command keywords. It reduces the program to its basename, with any capitalization of `git` printed as `git`. The guard reads its output as word arrays, so a flag cannot hide inside quotes and a commit message that mentions one is only the value of `-m`. `git-invocation.sh` is no longer used by this guard.
- **Flags (B-1, B-7).** `--no-verify`, and every prefix git accepts for it, is denied on `commit`, `push`, `merge`, `rebase`, `am`, and `pull`. The shortest prefix is `--no-veri`, except `--no-v` on `am`, which has no `--verbose`. `-n` is denied on `commit` and `am`, alone or in a bundled cluster, except where the `n` belongs to an attached argument. Values of value-taking options (`-m`, `-F`, `-X`, and others per subcommand) and everything after `--` are not read as flags. `git log -n`, `git push -n`, `git merge -n`, and `git pull -n` stay allowed.
- **Hook-manager variables (B-2, B-7).** `HUSKY=0`, `HUSKY_SKIP_HOOKS=1` or `true`, `SKIP`, `LEFTHOOK=0` or `false`, and `LEFTHOOK_EXCLUDE` are denied on a hook-running git command. The guard catches them as a prefix, through `env` or `sudo`, and through every export form in the same command: `export`, `declare -x`, `typeset -x`, `export NAME` before or after a plain assignment, and `set -a`. A plain, unexported assignment stays allowed, because bash does not pass it to git.
- **Config (B-3, B-8).** The guard denies a `core.hooksPath` override on a hook-running command through `-c`, `--config-env`, `GIT_CONFIG_KEY_n`, or `GIT_CONFIG_PARAMETERS`, with the key matched case-insensitively. It denies an `include.path` or `includeIf` setting on a hook-running command, and another config file for one (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `HOME`, `XDG_CONFIG_HOME`). It denies a git alias whose expansion skips hooks, which it judges by running the expansion through the guard itself. It denies a shell function or alias named `git`, and `git config` writes to `core.hooksPath`, the include keys, or a hook-skipping alias in any spelling: global options, quoted keys, and the `set` and `unset` subcommand forms. The old regex check for `git config core.hooksPath` is replaced, which also stops it denying `git config core.hooksPath 2>/dev/null`.
- **Hook files (B-4, B-9).** The guard denies deleting, moving, disabling, truncating, or overwriting a file under `.git/hooks`. Paths may be relative, absolute, `//` and `./` variants, globs that match `hooks`, `$(git rev-parse --git-path hooks)` and `--git-dir` substitutions, or relative to an earlier `cd` in the same command. The covered tools are `rm`, `unlink`, `shred`, `truncate`, `mv`, `cp`, `ln`, `install`, `rsync`, `tee`, `chown`, `chmod` (only a mode that removes owner execute), `dd of=`, in-place `sed` and `perl`, `find` with a delete or modifying exec, `rm -r` or `chmod -R` on `.git`, and output redirects including `>|`. Sample files, `.bak` backups inside `.git/hooks`, installing a hook from a tracked `*.sample` template, `chmod +x`, and read-only `find -exec` stay allowed.
- **Settings.** The two `ask` rules for `git commit --no-verify*` and `git commit -n *` are removed, because the hook now denies those forms first.
- **Fail-closed parsing and speed (B-10, B-13).** A later line bash cannot parse no longer hides the lines before it, because the parser keeps everything up to the syntax error. If the parser is missing, `python3` fails (the macOS stub without developer tools), or the helper raises, any command naming git or hooks as a word is denied. A bare redirect (`> .git/hooks/pre-commit`, `exec > ...`) is denied. Path resolution uses only bash string operations and runs only for the file tools that can touch a hook, so a 1500-argument `rm` is decided in under 300ms; before, it forked two processes per argument, took about 5 seconds, and got the hook process killed, which lets the call through.
- **Round-two coverage (B-11, B-12).** Substitutions inside double quotes and unquoted heredoc bodies; shell options before `-c` (`bash -euo pipefail -c`); text fed to a shell by herestring or pipe; `$(which git)` as the program; a shell alias of any name whose value skips hooks; brace expansion in hook paths; `find ! -name '*.sample' -delete`; renaming a hook to `.bak` and then running a hook-running command in the same call; writing `.git/config`, `~/.gitconfig`, or the XDG git config directly; `pushd`; `..` in paths; `chmod 0` and `--reference`; `git --attr-source`; the last `-c alias.X` winning; and `rev-parse --git-path <any path>`. An absolute `.git` outside the repository (a throwaway fixture) may be removed.
- **Fixtures and docs.** The new fixture `claude/enforce/tests/hook-bypass-guard.test.sh` has 401 cases (245 deny, 138 allow, 18 fail-closed and timing cases), one section per slice. The manifest notes for R-107 and R-203, the README's gate paragraph, and `.gitignore` (`__pycache__/`) are updated, and `hook-hashes.txt` is regenerated.

## Architectural decisions

- **Chosen: a Python parser beside the bash hook.** Every miss the first review confirmed came from quoting, escaping, or command structure, which regular expressions and `awk` handle only approximately. `dependency-add-scan.py` already set the pattern of a Python companion to a bash hook. **Alternative:** Python's `shlex`. **Why not:** it does not treat newlines as separators, cannot tell a quoted `>` from a redirect, and mishandles `$'...'`, so each gap would need a pre-pass. The hand-written tokenizer is about 200 lines and states each rule once. **Cost:** the Bash hook chain measured about 400ms per call against a budget of about 600ms, up from about 420ms before the parser once load is accounted for; the guard itself takes about 60ms.
- **Chosen: fail closed without the parser.** If `python3` or the helper is missing, any command mentioning git or hooks is denied with a message naming `sync.sh`. The first version silently lost the global-option handling when its helper was absent.
- **Chosen: judge an alias by running its expansion through the guard.** An alias value is a command, and the guard already knows how to judge commands; a second rule set for alias values would drift from the first. Recursion is capped at depth 3, and hitting the cap is treated as a deny.
- **Chosen: deny, not ask.** An ask on a hook skip is the path of least resistance for an agent whose commit a hook just rejected, and R-203 already says the agent never bypasses a guard.
- **Chosen: fix the common forms here and put the backstop in IAN-155.** A text guard cannot see a variable that holds the flag, a script file that runs git, or a symlinked hooks directory. The owner chose, on 2026-09-19, to close the forms an agent types by habit or accident in this PR and to add a spelling-independent check (pre-commit stamps each approved commit, pre-push refuses unstamped ones) separately.
- **Chosen: keep the checks in `destructive-command-guard.sh` for now.** The guard file grew to about 750 lines, most of it the git-hook section. Moving that section into its own hook would give each file one responsibility (R-318) but adds a registration, a process per Bash call, and a change to the generated Codex and Cursor ports. That split is worth a small follow-up refactor, with the fixture as its contract.
- **Test author: `test-author` subagent for all thirteen slices (fallback: Codex usage limit reached).** Each run ended blocked by the R-509 stop gate, because the gate does not know a test author is meant to return red; IAN-156 tracks that.

## Known gaps

Out of scope by design, tracked in IAN-155's spelling-independent backstop: a variable that holds the flag (`f=--no-verify; git commit $f`), a script file that runs git, a symlinked hooks directory, interpreter one-liners that delete files (`python3 -c "os.remove(...)"`), wrappers this guard does not list (`caffeinate`, `stdbuf`, `direnv exec`, `env -S`), `tar -C .git/hooks`, `find . -path '*hooks*' -delete` from the repository root, a custom `core.hooksPath` directory such as `.githooks/`, and `git rebase -x "<command>"` strings. `SKIP=` is denied on every hook-running git command, including repositories that do not use the pre-commit framework.
- Probes outside the fixture: a heredoc whose body mentions `--no-verify` is allowed; `bash <<EOF` containing a skip is denied; `$(git commit --no-verify)` is denied.

## Reflection

- **What I understand now.** A command guard is a shell parser first and a rule list second. Every false positive in the first design came from quoted text, and every miss came from structure the text match could not see: a global option, an `export` two commands earlier, a wrapper, an escaped character.
- **What I got wrong first.** I shipped four slices on regular expressions and called the result "every way to skip hooks". The adversarial review found nine classes of live bypass in about fifteen minutes. The claim should have been scoped from the start, and the parser should have come before the rules.
- **Smaller mistakes.** B-2's first implementation denied nothing, because the segment splitter ended without a newline and `read` dropped the only segment. An `&&` chain through `tail` hid a failing `validate` on slice 9, so its commit landed before I re-checked the latency test by hand; later slices gate the commit on the exit status. The parser at first returned nothing on an unclosed quote, reasoning that bash never runs such a command, which is false for every line before the error. And a fork per path argument made the guard slow enough to be killed, which is its own fail-open path.
- **Process gaps found.** The stop gate blocks test authors on their intended RED (IAN-156), and two other guards misread quoted text as commands (IAN-157).
