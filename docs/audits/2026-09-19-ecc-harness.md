# ECC harness audit: comparison with this harness and a porting plan

Date: 2026-09-19

## Scope

This audit reviews ECC ("Everything Claude Code", github.com/affaan-m/ECC, v2.2.1, commit `07756ce`) as a third-party Claude Code harness. It answers three questions: whether ECC is safe to install alongside this harness, how its strengths and weaknesses compare with this harness's, and which of its features are worth porting.

ECC was shallow-cloned into a throwaway directory. Nothing was installed, no ECC hook ran against the live `~/.claude`, and ECC's test suite ran only with `HOME` pointed at a scratch directory. Six read-only reviewers covered security, enforcement quality, a head-to-head comparison, and three feature sweeps (runtime scripts, the 292 skills, and the agents, commands, and rules). The dispatcher re-checked the load-bearing claims against both codebases before writing this report. ECC paths below are relative to the ECC repository root; this harness's paths are relative to this repository.

ECC is large: 292 skills, 68 agents, 94 commands, 122 rule files, 55 hook scripts, about 60 CLI scripts, a Rust dashboard (`ecc2/`), and install targets for 15 agent tools.

## Verdict

Do not install ECC's hook runtime. Its most important enforcement hooks do not reliably block, one hook executes commands defined by whatever repository is open, and its observation hook writes unredacted secrets to disk. ECC's value to this harness is as a catalogue of ideas: 24 specific mechanisms, rules, and skills are worth rewriting into this harness's conventions, listed in the porting plan below.

## Weaknesses compared

### ECC

1. **GateGuard denies once and allows the identical retry.** `scripts/hooks/gateguard-fact-force.js:1440` returns `rawInput` under the comment `// allow retry after facts presented` (line 1432). Subagent edits skip the gate entirely (line 1380). Its deny message tells the model how to disable it: "run this session with `ECC_GATEGUARD=off`" (line 1309).
2. **The destructive classifier misses trivial rewordings.** Unflagged in a 47-variant probe: `sudo rm -rf`, `env rm -rf`, `xargs rm`, `psql -c "DROP TABLE users"`, `git push --delete origin main`, `find . -delete`, `terraform destroy`, `kubectl delete ns`, `python -c "shutil.rmtree(...)"`.
3. **Security hooks fail open.** `scripts/hooks/plugin-hook-bootstrap.js:279-296` sets `process.exitCode = 0` on bootstrap failure, signal, or timeout; `run-with-flags.js:258` does the same on exceptions. Config protection is reachable through `sed -i` because it matches only `Write|Edit|MultiEdit`.
4. **The MCP health-check hook executes repository-defined commands.** `scripts/hooks/mcp-health-check.js:69-74` reads `.claude.json` and `.claude/settings.json` from the current directory before the user's own config, and line 409 spawns the named server with the full environment. A cloned repository that defines a common server name runs its payload the next time that MCP tool is called, outside Claude Code's MCP approval flow.
5. **Observation capture leaks secrets.** `skills/continuous-learning-v2/hooks/observe.sh` stores up to 5 KB of every tool input and output for 30 days under `~/.local/share`. Its keyword-anchored scrubber (line 344) passed a database URL containing a password, a PEM private key, an AWS access key ID, and a live Stripe key through unredacted in a synthetic test.
6. **Skill mirrors have drifted.** Every shared skill differs between `skills/` and `.agents/skills`, `.kiro/skills`, and `.cursor/skills`; `.kiro/skills/python-testing/SKILL.md` has about 940 changed lines against the canonical copy. The Codex skill tests check that the directory is populated and that frontmatter is valid, but no test compares any mirror with `skills/`.
7. **Cost.** A full install loads about 28k tokens of skill, agent, and command descriptions into every session and spawns about 12 Node processes per Bash call (about 1 s CPU).
8. **Hook kill switches.** `ECC_HOOKS_ENABLED`, `ECC_DISABLED_HOOKS`, `ECC_HOOK_PROFILE`, and an unprotected `ecc/setup.json` let the agent disable its own guards indirectly.

### This harness

These come from this harness's own `2026-09-18-criticism.md`, plus gaps this comparison exposed.

1. **No outcome evidence.** The harness measures rule fires and activity, not whether shipped code has fewer defects or ships faster.
2. **The suite can be red on a fresh local run** while `main` is internally coherent; some fixtures read ambient harness state.
3. **Cross-tool parity overclaims.** Port status reports that an event is reachable in Codex or Cursor as if the rule were enforced there.
4. **The paid rule judge is inert** until a credential is installed manually, with no readiness signal.
5. **Gaps exposed by ECC:**
   - project lint and format configs are unprotected, so R-204 and R-405 depend on recall;
   - `--no-verify` is an `ask` prompt, not a deny;
   - no cost, skill-usage, or tool-loop telemetry;
   - `NotebookEdit` is not matched by the `Write|Edit` PreToolUse hooks, so secret-scan, protected-path-guard, and structure-gate never see notebook edits;
   - `rule-judge.yml` keeps `ANTHROPIC_API_KEY` under `pull_request_target` and is safe only because it checks out `base.sha`, which no test pins;
   - nothing rejects invisible or bidirectional Unicode in the markdown loaded as instructions.

## Porting plan

Every port is a rewrite, not a copy. ECC's prose carries rationale and em dashes, which R-206 and R-207 forbid, and several ECC mechanisms need the gaps closed that this audit found. Ranks combine value, effort, and how directly each closes a gap in this harness.

## Do not port

1. **Hook profiles and kill switches** (`ECC_DISABLED_HOOKS`, `ECC_HOOK_PROFILE`, `ECC_GATEGUARD=off`). They conflict with R-203.
2. **LLM transcript summaries at PreCompact and SessionEnd** (`scripts/lib/llm-summary.js:153` runs `claude -p` over unredacted transcript text with no tool restriction). They conflict with R-104 and R-202.
3. **Automatic skill extraction and observation capture** (`evaluate-session.js`, `continuous-learning-v2`). Unreviewed model-written skills conflict with R-603, and the capture leaks secrets.
4. **GateGuard.** It is bypassable on retry, costs a round trip per file, and advertises an external `pip install`.
5. **The MCP health-check hook**, for the command-execution finding above.
6. **The full skill and agent catalogue and `mcp-configs/`**, for context cost and unpinned `npx -y ...@latest` servers.
7. **Skills that run third-party tools against the harness**: `security-scan` runs the unpinned `npx ecc-agentshield` package, and its opt-in `--fix` mode edits settings; `repo-scan` installs into the live `~/.claude`.

## Contradictions to keep in mind when porting

ECC rules conflict with this harness in about 17 places. The ones most likely to slip in through a careless port:

- parallel dispatch by default, where R-703 requires a canary;
- 50-line functions and an 800-line file ceiling, where R-322 and R-318 differ;
- `lib/` directories, which R-306 bans;
- a `{success, data, error}` envelope, where `CLAUDE-BACKEND.md` uses a different shape;
- 80% coverage, where the project convention is 60%;
- scoped Vue `<style>` blocks, where this harness uses SCSS modules;
- auto-imported Nuxt composables, where this harness requires explicit `#imports`;
- `includeCoAuthoredBy: false`, which drops commit attribution.

- **P1:** port items 1 through 5 (lint config protection, hook-bypass deny, project-config trust scan, Unicode gate, workflow-security test).
- **P2:** items 6 and 7 (NotebookEdit matcher, network and credential-path denies) and items 8 through 13 go to `claude/ISSUES.md` per R-802.
- **P3:** items 14 through 24.
